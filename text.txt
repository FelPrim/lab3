ЯЯ пишу клиент-серверное приложение для видеосвязи на C++. Мне нужен клиент, удовлетворяющий следующим условиям:
1. У него есть слушающий tcp-сокет, который коннектится к серверу с заранее заданным IP-адресом и портом
2. У него есть слушающий udp-сокет, который умеет отправлять и принимать пакеты с данными.
3. С каждым tcp-соединением (после connect) у него есть протокол общения. У сообщений есть тип (он передаётся первым байтом) и содержание, которое зависит от типа. Соответственно, все типы сообщений от клиента:
1) Посылка UDP-адреса от клиента к серверу
2) Разрыв соединения (как сообщение и как просто разрыв tcp-соединения)
3) Запрос на создание трансляции
4) Запрос на завершение трансляции
5) Запрос на подсоединение к трансляции по id
6) Запрос на выход из трансляции
Все типы сообщений от сервера к клиенту:
1) Ответ на запрос о создании трансляции
2) Пересылка слушателям трансляции информации о том, что трансляция завершилась
3) Ответ на запрос зрителя о подсоединении к трансляции (передача информации о трансляции)
4) Сообщение владельцу трансляции о том, что есть участники (и нужно передавать данные)
5) Сообщение владельцу трансляции о том, что нет участников (передавать данные тогда - пустая трата ресурсов)
У меня есть наработки того, как должен выглядеть сервер на C
Просто комментарии:
Из ТЗ не следует, что пользователь может смотреть только 1 трансляцию одновременно.
Из ТЗ не следует, что пользователь может вести только 1 трансляцию одновременно (например, камера и захват рабочего стола)
Большинство статических массивов считаются плотными - т.е. при удалении элемента из массива последний элемент меняется с удалённым местами. За счёт этого такие массивы можно обходить примерно с такой же логикой, как строки в C.
Клиент может вести не более чем MAX_OUTPUT трансляций и быть смотрящим не более чем MAX_INPUT трансляций. 
MAX_OUTPUT = MAX_INPUT = 4
3. UDP-трафик между ними проходит за счёт моего простейшего протокола. Он будет выглядеть примерно таким образом:
4 байт - id трансляции
4 байта - номер пакета
1192 байт - тело пакета с относительно полезной информацией
6. По первому байту TCP-сообщения определяется его тип, в зависимости от типа у него может быть разный размер. Тип как бы задаёт однозначный алгоритм, с помощью которого сообщение можно прочитать. Например, когда сервер отсылает пользователю информацию о трансляции, он отсылает её таким образом:
1 байт - тип
4 байт - id трансляции

Если тип сообщения CLIENT_UDP_ADDR:
1 байт - тип сообщения
остальные байты - UDP-адрес клиента. После завершения получения UDP-адреса клиента сервер может, теоретически, пересылать ему пакеты. 
Для этого клиент должен отправить пару пакетов, наполненных 0, серверу - чтобы пробить NAT
Если тип сообщения CLIENT_DISCONNECT:
1 байт - тип сообщения
При отсоединении клиента он выходит из всех трансляций, в которых он был до этого, и завершает все свои трансляции.
Если тип сообщения CLIENT_STREAM_CREATE:
1 байт - тип сообщения
Сервер должен создать новую трансляцию и отправить клиенту информацию о ней. см SERVER_STREAM_CREATED
Если тип сообщения CLIENT_STREAM_DELETE:
1 байт - тип сообщения
4 байт - id трансляции
Трансляция завершается, о чём сервер оповещает всех зрителей, которые были в трансляции. см SERVER_STREAM_DELETED
Если тип сообщения CLIENT_STREAM_JOIN:
1 байт - тип сообщения
4 байт - id трансляции
Во-первых, сервер должен отправить клиенту информацию о трансляции. см SERVER_STREAM_JOINED
Во-вторых, возможно, состояние трансляции поменялось (может быть, там не было участников). Если это так, то сервер должен отправить владельцу SERVER_STREAM_START
Если тип сообщения CLIENT_STREAM_LEAVE:
1 байт - тип сообщения
4 байт - id трансляции
Сервер должен перестать пересылать данные этой трансляции этому клиенту. Состояние трансляции поменялось (может быть, это был единственный зритель). Если это последний зритель, то сервер должен отправить владельцу SERVER_STREAM_END

Если тип сообщения SERVER_STREAM_CREATED:
1 байт - тип сообщения
4 байт - id трансляции
После того, как клиент получает id трансляции, он его:
1) сохраняет
2) преобразует в строку следующим образом:
 char name[7];
 for (int i = 0; i < 6; ++i){
	name[i] = id%26 + 'A';
	id /= 26;
}
name[6] = '\0';
И выводит на экран

Если тип сообщения SERVER_STREAM_DELETED:
1 байт - тип сообщения
4 байт - id трансляции
Клиент удаляет декодировщик, выделяемый под трансляцию. Также, очевидно, что окно, в котором отображался стрим, убирается
Если тип сообщения SERVER_STREAM_JOINED:
1 байт - тип сообщения
4 байт - id трансляции
Клиент выделяет декодировщик и ждёт пакеты. Появляется новое окно, в котором, в конце концов, должно оказаться изображение.
Если тип сообщения SERVER_STREAM_START:
1 байт - тип сообщения
4 байт - id конференции
Клиент начинает отправлять пакеты, соответствующие трансляции, серверу. Также у клиента всплывает надпись "Есть зрители"
Если тип сообщения SERVER_STREAM_END:
1 байт - тип сообщения
4 байт - id конференции
Клиент перестаёт отправлять пакеты, соответствующие трансляции, серверу. У клиента надпись "Есть зрители" заменяется на "Нет зрителей".

Как должен выглядеть GUI пользователя:
Кнопки: 
Начать трансляцию
Подсоединиться к трансляции

При нажатии на любую из них открывается подокно, соответствующее 1 трансляции.
Если клиент выбирает Начать трансляцию, то он выделяет для этого отдельный поток и у него показывается окно с трансляцией. В нём он выбираем устройство, которое будет показывать. После этого:
1. В подокне показывается захват видеоустройства, которое клиент планирует стримить.
2. Стартует кодировщик и клиент отправляет CLIENT_STREAM_CREATE. 
После этого он ждёт SERVER_STREAM_CREATE. Как только он его получает:
1. В подокне появляется надпись "Нет зрителей". Также есть кнопка "Завершить трансляцию".
2. В подконе появляется надпись "Id трансляции: ______". Этот id получается из целого числа, задававшего трансляцию, упомянутым выше способом.
После этого клиент ждёт SERVER_STREAM_START. Как только он его получает -> клиент начинает отправлять данные на сервер + надпись меняется на "Есть зрители"

После этого клиент, кроме прочего, ждёт SERVER_STREAM_END. Как только его получает -> перестаёт отправлять данные на сервер (+ надпись меняется)
Если же клиент в любой момент нажмёт на кнопку завершить трансляцию, то на сервер будет отправлен CLIENT_STREAM_DELETE и подокно убирается, как и поток.

Если же клиент кликает Подсоединиться к трансляции:
1. Поле для ввода "Id трансляции: ______"
2. Кнопка "Покинуть трансляцию"
Для этого выделяется отдельный поток и у него показывается окно с трансляцией. В нём он заполняет поле "Id трансляции: ______". После этого (после проверки ввода на то, что это только загланвные латинские буквы) введёная строка конвертируется через
int stream_id = 0;
for (int i = 0; i < 6; ++i){
	stream_id *= 26;
	stream_id += name[i]-'A';
}
return stream_id;
к целому числу, которое используется для отправки CLIENT_STREAM_JOIN.
Также у клиента стартует декодировщик.
После этого клиент ждёт SERVER_STREAM_JOINED. Как только он его получает, то он должен, в теории, начать получать пакеты, которые после дешифровки станут изображением в подокне.
После этого клиент, кроме прочего, ждёт SERVER_STREAM_DELETE. Как только его получает -> подокно удаляется.

Если же клиент в любой момент нажмёт кнопку "Покинуть трансляцию", то на сервер будет отправлен CLIENT_STREAM_LEAVE.
